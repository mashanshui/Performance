# 项目概览与能力状态

[返回导航](README.md)

## 项目定位

Performance 是 Android 性能工具与采集上报项目。`app` 提供演示页面，`nativelib` 提供统一 SDK、事件队列、网络通信及 Kotlin/JNI 工具。应用通过 `PerformanceSdk.initialize(application, appKey, config)` 显式启动 SDK；调用成功后，SDK 会按配置自动创建各个 Reporter，以及主进程可用时的 Activity 泄漏检测器和 KOOM 监控。

当前重点链路为 JVM Crash、Rhea Jank ZIP、场景 FPS、主进程内存指标，以及独立的 Activity 泄漏检测与 KOOM OOM 触发。泄漏检测不产生 `memory_sample` 事件，也不复用 PSS/VSS/Java heap 的指标队列。库中还保留 Looper 消息历史、超时抓栈、CPU 空闲检测、线程池、绑核与 GC Hook 等工具；它们是否被调用，需要沿实际入口确认。

## 范围与平台边界

- Gradle 当前只声明 `:app` 和 `:nativelib`；本仓库不包含服务端或 Rhea 处理器实现。客户端通过 Maven Local 使用 `rhea-inhouse:1.0.3`，服务端当前固定使用 `rhea-trace-processor:1.0.2`。
- `nativelib` 的 `minSdk=21`，示例应用的 `minSdk=23`；这不表示每项能力从相应最低版本起都可用。
- 本地 CMake 原生构建限定 `arm64-v8a`。
- FPS 需要 API 24+、主进程与硬件加速 Window，且受 `jank.enabled && jank.fps.enabled` 控制。
- Activity 泄漏检测与 KOOM 联动只接受 Android API 21..36 的主进程；它受 `memoryLeak.enabled` 控制，不依赖 `memory.enabled`，不使用指标 Reporter 的持久队列，而是使用独立 report 队列；HTTP 请求不包含 HPROF。
- Jank 是否可用由 Rhea 初始化结果决定；预期平台降级不等于整个 SDK 初始化失败。有效产物必须携带 UUID v4 `processId` 和 `threadScope=main`，成功上传只认 HTTP 200。
- 当前 Crash 载荷为 JVM 致命异常；本仓库没有完成 native crash、系统 ANR 或非致命异常的统一采集上报链路。
- CPU、GC 工具没有接入统一指标上传；内存指标已接入统一事件队列并完成此前设备与服务端闭环，设备功耗、跨 Android 版本和长周期后台行为仍需单独验收。

## 本轮验证范围

已有内存指标链路的历史证据包括 JVM 测试以及 2026-09-09 的 Pixel 4 XL/API 33/arm64-v8a 和 ClickHouse `memory_sample` 验证；这些证据只覆盖 PSS/VSS/Java heap 指标，不覆盖 Activity 泄漏检测。2026-09-12 使用同一 Gradle 8.13 发行版的直接 `gradle.bat` 执行 `:nativelib:testDebugUnitTest :app:assembleDebug` 成功；在 Huawei EML-AL00/API 29 上安装 Debug APK 后，以示例快速配置完成真实 KOOM dump、独立分析进程建索引、Activity 泄漏路径分析和 JSON 输出验证。该设备证据不代表默认 10 次重检、完整服务端上传或跨设备兼容性已通过。

后续执行验证时记录：日期、源码版本、命令、结果、设备/API/ABI（如适用）、产物或报告位置。测试覆盖位置见 [构建测试](11-构建测试与本地发布.md)。

## 当前优先关注

1. Crash 协议代码已切换到 schema v2、`packageName` 和 UUID v4 `processId`，仍需用修复后的真实请求完成设备与服务端 accepted/duplicate 联调。
2. Jank 的 UUID v4 `processId`、主线程 manifest、HTTP 200 成功判定和 403 永久错误分类已同步；当前 Rhea 1.0.3 已在 EML-AL00/API 29 生成并由 Processor 解析实际 ZIP，仍需完成服务端接收联调。
3. FPS 当前桶尚未结算的数据不进入 Store 快照，不能承诺异常退出最多只丢一个快照周期。
4. 内存链路已实现并完成一次真实设备到 ClickHouse 的上传、重复事件和查询验收；前后台长周期、断电恢复、功耗、跨版本和若干独立工具仍有待完善处。
5. Activity 泄漏检测已接入 SDK 初始化和关闭/回滚链路，report JSON 已接入独立持久上传链路；真实设备快速配置已验证 KOOM dump 和 `:heap_analysis` 分析，多进程异常回滚、默认 10 次重检、服务端联调及更广 API/设备覆盖仍待验证。

具体证据与后续验证方式集中在 [常见问题与待验证事项](12-常见问题与待验证事项.md)。这些是当前待处理项；相关实现改动已在源码中完成，本次收尾只修正本页文档表述，不应将其理解为本轮没有实现改动。
