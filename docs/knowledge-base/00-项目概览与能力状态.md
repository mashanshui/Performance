# 项目概览与能力状态

[返回导航](README.md)

## 项目定位

Performance 是 Android 性能工具与采集上报项目。`app` 提供演示页面，`nativelib` 提供统一 SDK、事件队列、网络通信及 Kotlin/JNI 工具。应用通过 `PerformanceSdk.initialize(application, appKey, config)` 显式启动 SDK。

当前重点链路为 JVM Crash、Rhea Jank ZIP 和场景 FPS。库中还保留 Looper 消息历史、超时抓栈、CPU 空闲检测、线程池、绑核与 GC Hook 等工具；它们是否被调用，需要沿实际入口确认。

## 当前能力

| 能力 | 代码与接入状态 | 验证入口或边界 |
| --- | --- | --- |
| 统一 SDK | 管理 Crash/Jank/FPS、共享网络资源、幂等初始化和关闭 | 配置与元数据有 JVM 测试；完整组件生命周期仍需 Android 环境验证 |
| JVM Crash | 捕获未处理异常，同时生成 `app_start`；持久化并批量上传 | 工厂、队列、上传器与网络有测试；当前协议与服务端存在差异 |
| Jank | SDK 初始化 Rhea；示例 Looper 在消息结束后构造事件并导出 ZIP | 队列、重试、原字节上传有测试；实际采样和 ZIP 版本依赖所解析的 Rhea AAR |
| FPS | SDK 绑定 Activity/Window，采集有效 FrameMetrics，场景汇总并持久化 | 有算法、存储、上传器测试与页面入口仪器测试 |
| 消息历史 | `MessageCollect` 可显式注册；读取时还反射遍历待执行消息 | 未接入 SDK 自动启动；未发现专门测试 |
| 消息超时抓栈 | `MessageTimeoutMonitor` 的协程监控与主线程堆栈输出 | 需显式注册监听；不是已完成的系统 ANR 上报 |
| 线程/原生工具 | 有 CPU/IO 线程池、优先级、绑核、GC Hook、CPU/内存读取 | 有独立演示代码；缺少设备兼容矩阵和收益基准 |

## 范围与平台边界

- Gradle 当前只声明 `:app` 和 `:nativelib`；本仓库不包含服务端或 Rhea 处理器实现。
- `nativelib` 的 `minSdk=21`，示例应用的 `minSdk=23`；这不表示每项能力从相应最低版本起都可用。
- 本地 CMake 原生构建限定 `arm64-v8a`。
- FPS 需要 API 24+、主进程与硬件加速 Window，且受 `jank.enabled && jank.fps.enabled` 控制。
- Jank 是否可用由 Rhea 初始化结果决定；预期平台降级不等于整个 SDK 初始化失败。
- 当前 Crash 载荷为 JVM 致命异常；本仓库没有完成 native crash、系统 ANR 或非致命异常的统一采集上报链路。
- CPU、GC、内存工具没有接入统一指标上传；存在 Kotlin/JNI 方法不等于已形成线上监控能力。

本轮核对了源码、测试源码、构建声明、已有文档及本机 apm-server 契约，检查文档路径、链接与差异格式。没有运行 Gradle、设备或在线服务验收，不将历史构建产物或外部文档中的验收记录当成本项目本轮通过证据。

## 当前优先关注

1. Crash 当前为 schema v1 与 `appId` 字段，所核对服务端契约要求 v2 与 `packageName`。
2. Jank 的 HTTP 403 分类、成功 HTTP 状态校验与服务端契约有差异。
3. FPS 当前桶尚未结算的数据不进入 Store 快照，不能承诺异常退出最多只丢一个快照周期。
4. 示例配置、监听生命周期和若干独立工具仍有待完善处。

具体证据与后续验证方式集中在 [常见问题与待验证事项](12-常见问题与待验证事项.md)。这些是当前待处理项，本次文档整理没有修改相应实现。
