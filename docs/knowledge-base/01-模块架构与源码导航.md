## 线程与资源归属

| 执行位置 | 工作与释放方式 |
| --- | --- |
| 初始化调用线程 | 配置、元数据与组件创建；包含部分队列恢复/磁盘读取，不能概括为全部后台执行 |
| Looper 所在线程 | 同步通知所有监听器；示例主 Looper 回调运行在主线程 |
| `crash-upload` | Crash 定时与恢复上传；异常处理路径另有调用线程上的限时同步上传 |
| `jank-artifact-upload` | ZIP 队列对账、上传、重试与删除 |
| Rhea 导出回调 | 返回导出结果，Reporter 检查产物并入队；更新 UI 需主动切主线程 |
| `fps-frame-metrics` | Window 帧回调、内存累加和摘要输出 |
| `fps-upload` / `fps-persistence` | FPS 快照、封存事件上传、关闭时持久化 |

`PerformanceSdk.close()` 关闭其管理的 Reporter 和共享网络工厂；只有本次启动的 Rhea 才由 SDK 停止。独立线程池、CPUFreeHelper 和示例注册的 Looper 监听不归 SDK 自动回收。

## 边界与取舍

Reporter 负责触发与生命周期，Uploader 负责响应分类和队列状态，Store/Queue 负责文件。这使队列与重试可以在 JVM 上测试，但不能借此证明 Android 生命周期和 Rhea 原生行为。

四个 Reporter 共享 HTTP 客户端，但保留独立的事件模型、队列和成功判定。修改公共网络层应同时检查四条链路；修改某一链路时不要假设其他上传器具有相同校验。
