## 线程与资源归属

初始化调用线程负责配置、元数据、队列恢复和组件准备；功能内部的采集、文件和网络工作由各模块自己的线程池或 Handler 执行。`PerformanceSdk.close()` 按逆序关闭 Leak、Metrics、Jank、Crash 等功能，最后释放本次初始化创建的 Transport 会话。借用外部 OkHttp/Retrofit 的 Transport 会话不关闭外部连接池。独立 Looper 监听、原生线程工具和宿主自建线程不属于 SDK 自动回收范围。

Reporter/Component 负责功能生命周期，Uploader 负责响应分类，Store/Queue 负责文件状态。Crash、Jank、Metrics 和 Leak 保持独立事件模型、队列和成功判定，只共享事件上下文和 HTTP 会话。Core/Transport 不依赖任何业务模块，业务模块之间不互相依赖。

## 验证依据

当前主机侧测试入口分布在各模块 `src/test`：Core/Transport、Crash、Jank、Metrics、Leak 及 SDK 配置测试；Native Tools 通过 `:performance-native-tools:assembleRelease` 核对 `arm64-v8a` AAR；`verification/modular-consumer` 已完成仅 Crash、仅 Metrics 和全量 SDK 三个外部消费者的 Debug/Release（含 R8）构建。设备和真实服务端仍按 [12 常见问题与待验证事项](12-常见问题与待验证事项.md) 记录，不能用旧 `:nativelib` 历史记录替代本轮模块化证据。
