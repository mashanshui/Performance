## 线程与资源归属

| 执行位置 | 工作与释放方式 |
| --- | --- |
| 初始化调用线程 | 配置、元数据与组件创建；包含部分队列恢复/磁盘读取，不能概括为全部后台执行 |
| Looper 所在线程 | 同步通知所有监听器；示例主 Looper 回调运行在主线程 |
| `crash-upload` | Crash 定时与恢复上传；异常处理路径另有调用线程上的限时同步上传 |
| `jank-artifact-upload` | ZIP 队列对账、上传、重试与删除 |
| Rhea 导出回调 | 返回导出结果，Reporter 检查产物并入队；更新 UI 需主动切主线程 |
| `fps-frame-metrics` | Window 帧回调、内存累加和摘要输出 |
| `fps-upload` / `fps-persistence` | FPS 快照、封存事件上传、关闭时持久化 |
| `memory-sampling` / `memory-upload` | PSS/VSS/Java heap 采集、事件落盘和批量上传 |
| `memory-leak-report-upload` | report 队列恢复、multipart 上传、Retry-After 退避和确认删除 |
| `activity-leak-watcher` | Activity 生命周期回调入队；GC、finalization、弱引用重检和泄漏回调均在 HandlerThread 执行 |
| KOOM 后台线程/分析服务 | `OOMMonitor` dump 触发、Hprof 生成及外部分析；SDK 只上传 report JSON，不上传 HPROF |

`PerformanceSdk.close()` 关闭其管理的四个数据 Reporter、Activity 泄漏检测器和共享网络工厂；只有本次启动的 Rhea 与 KOOM 循环才由 SDK 停止。KOOM 的进程级 `mHasDumped` 不会因 stop/close 重置。独立线程池、CPUFreeHelper 和示例注册的 Looper 监听不归 SDK 自动回收。

## 边界与取舍

Reporter 负责触发与生命周期，Uploader 负责响应分类和队列状态，Store/Queue 负责文件。这使队列与重试可以在 JVM 上测试，但不能借此证明 Android 生命周期和 Rhea 原生行为。

Crash、Jank、FPS、内存指标和内存泄漏 report 共享 HTTP 客户端与进程级运行身份，但保留独立的事件模型、队列和成功判定。Activity 泄漏检测不是 `memory_sample` Reporter；其 report 已接入独立服务端接口，HPROF 仍不上传。Jank 只把 HTTP 200 视为成功，403 进入永久删除路径；批次 JSON 链路由各自上传器校验 HTTP 200 与业务响应。修改公共网络层应同时检查五条上传链路；修改某一链路时不要假设其他上传器具有相同校验。

## 验证依据

当前结构由上述生产源码及 [测试目录](../../nativelib/src/test/java/com/shanshui/performance) 核对。`:nativelib:test` 已覆盖运行身份、report multipart、队列恢复、Jank HTTP 状态和上传错误分类并通过；Activity 泄漏相关仪器测试已执行：`:nativelib:connectedDebugAndroidTest` 在 Pixel 4 XL/Android 13 上 6/6 通过。2026-09-12 又在 Huawei EML-AL00/Android API 29 以快速配置验证了真实 KOOM dump、`:heap_analysis` 分析进程和 JSON 产物；本轮同一设备的 Rhea 1.0.3 AndroidTest 进一步验证了采样 extra、通用/Jank manifest、ZIP Processor 解析及同/异 processId 初始化结果。默认 10 次重检、跨设备兼容、服务端联调和并发压力仍未验证。
