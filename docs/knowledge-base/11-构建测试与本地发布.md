## Rhea 本地依赖

[settings.gradle.kts](../../settings.gradle.kts) 为项目声明 `mavenLocal()` 和远程仓库；库依赖
`io.github.mashanshui:rhea-inhouse:1.0.3`，并标记 changing，确保本地开发阶段重新检查同版本制品。
客户端使用的 Rhea API 为 `1.0.3`，服务端 Jank 解析器仍固定为
`io.github.mashanshui:rhea-trace-processor:1.0.2`。

因此重新下载远端同名包无法替代本机依赖准备。缺少该坐标时应先在 Rhea 项目生成并发布正确制品；同版本重新发布也需要确认消费者真正解析到的新产物。仅看到坐标相同不能确认 ZIP 协议与 API 一致。

## 常用命令

以下 PowerShell 命令在项目根目录执行，属于操作指南；本轮对其中的核心构建组合进行了 Wrapper 与直接发行版两种方式的验证，结果见后文：

~~~powershell
# 核对 Wrapper 和实际运行 JVM。
.\gradlew.bat --version

# 库 JVM 单测与示例应用构建。
.\gradlew.bat :nativelib:testDebugUnitTest
.\gradlew.bat :app:testDebugUnitTest :app:assembleDebug

# 按变更范围运行项目检查。
.\gradlew.bat check

# 仅在有明确设备验证任务和可用设备时运行。
.\gradlew.bat connectedAndroidTest
~~~

构建失败先复现具体任务，再处理运行 JDK、依赖解析或模块配置。缓存写入失败时检查实际 Gradle user home 的权限；不要把切换缓存目录误当成已经准备好 Rhea Maven Local。

## App 编译期 buildId

`app/build.gradle.kts` 在 Gradle 配置阶段生成一次 `PERFORMANCE_BUILD_ID`，并通过
`BuildConfig.PERFORMANCE_BUILD_ID` 编译进 App。格式为
`versionName-versionCode-UTC时间戳-8位随机十六进制`。同一次 Gradle 命令生成的 Debug、Release
等变体共用该值，重新执行命令会生成新的值。

`App.onCreate` 将这个字段传给 `CrashConfig.buildId`。SDK 会把它作为 Crash、Jank、FPS、内存和
内存泄漏 report 的公共 buildId。Release APK、`app/build/outputs/mapping/release/mapping.txt`
和本次构建的 buildId 必须作为同一发布记录保存，服务端才能按 buildId 选择对应 mapping。

## App Release 签名构建

`app` 模块的 `release` 变体已绑定 [app/sign](../../app/sign) 签名文件，使用其中的 `key0` 条目。签名文件属于本机发布配置，执行 release 构建前需确认该文件存在；签名凭据不在知识库中重复记录。

~~~powershell
# 查看 release 变体使用的签名配置。
.\gradlew.bat :app:signingReport

# 构建已签名的 release APK。
.\gradlew.bat :app:assembleRelease
~~~

`app` 的 Release 开启 R8 代码压缩与资源收缩。`nativelib` 的 Release AAR 不单独混淆；它通过
`consumer-rules.pro` 向最终应用传递最小必要的保留规则：固定 `NativeLib` 的 JNI 类名和 native
方法名，保留 Gson 网络模型与持久化队列记录的字段名/泛型信息，以及注解、源码文件名和行号属性。
规则不保留整个 SDK，也不对 Gson、OkHttp 等第三方包添加宽泛 keep。

构建和检查混淆产物：

~~~powershell
# 检查 AAR 中的消费者规则，并使用该规则构建最终混淆 APK。
.\gradlew.bat :nativelib:bundleReleaseAar :app:assembleRelease

# Smoke test 绑定 Release APK；需要 ABI 与本库 arm64-v8a 原生实现匹配的已授权设备。
.\gradlew.bat :app:connectedAndroidTest '-Pandroid.testInstrumentationRunnerArguments.class=com.example.performance.ObfuscationSmokeTest'
~~~

Release R8 mapping 位于 `app/build/outputs/mapping/release/mapping.txt`。每次发布必须将该文件与
对应的 APK 一并归档；后续构建产生的 mapping 不能用于还原旧 APK 的堆栈。发布 AAR 时，其消费者规则
位于 AAR 根目录 `proguard.txt`，下游应用启用代码压缩后由 R8 自动合并。
示例 App 的 `app/proguard-rules.pro` 另精确保留 Release 仪器 runner 启动所需的
`androidx.tracing.Trace`、`kotlin.LazyKt` 和 `kotlin.Lazy`；这是演示应用的测试运行时配置，不属于 SDK
AAR 消费者规则，也不扩展为保留整个 AndroidX 或 Kotlin 包。

Performance `nativelib` 到远程仓库。远程仓库和 Maven Central 不属于上述任务。
