## 尚无本轮运行证据的边界

- Crash 在真实进程崩溃后、设备重启后及异常 handler 链中的完整行为。
- 多进程初始化：FPS 有主进程限制，Rhea 返回进程状态；Crash 没有同样的主进程保护，队列多进程并发需单独评估。
- FPS 60/90/120Hz 与小数刷新率设备、动态切换、旋转、后台/前台、非硬件加速 Window。
- 文件损坏、磁盘满、确认后删除失败、进程被杀与长时间离线下四种队列的恢复。
- Rhea 实际 AAR 的 API/manifest、当前设备 ART 兼容、ZIP 哈希与主线程采样证据。
- JNI 绑核成功率、GC Hook 安全退出和线程优先级的性能/功耗收益。
- 内存原始采集已在 Pixel 4 XL/API 33/arm64-v8a 上验证；设备烟测覆盖一次前后台切换、断网落盘和重启续传 ID 保持，真实网络上传、重复接收和 summary/trend 查询也已完成。事件构造/落盘细分耗时、长周期调度、断电恢复、功耗影响和其他 Android 版本仍无本轮证据。
- 当前客户端与服务端真实永久拒绝、503 后等待重试及 ClickHouse 长期容量仍未在本轮设备上验证。

## 本轮真实联调记录

- 日期：2026-09-09；设备：Pixel 4 XL，Android API 33，arm64-v8a。
- 服务端：本机 apm-server，ClickHouse 模式；首次请求因未执行 `005_memory_metrics.sql` 返回 HTTP 500（底层 ClickHouse 404 表不存在），迁移完成后恢复 HTTP 200。
- 上传结果：设备真实采样写入 `apm_memory_sample`；相同事件第一次重放 `accepted=1`，第二次重放 `duplicate=1`，客户端随后删除重复事件，dead-letter 为 0。
- 查询结果：授权 Session 下，2026-09-09 UTC 日范围、`processName=com.example.performance` 返回 12 个去重样本，其中 `foreground=true` 为 11 个、`foreground=false` 为 1 个，`scene=com.example.performance.MainActivity` 为 7 个；PSS/VSS/Java 堆三项状态均为 `ok`，数据源为 `clickhouse`。
