# 主进程运行期内存峰值规范

## Purpose

为主进程提供可恢复的运行期内存观测峰值：分别保存PSS、VSS与Java堆最大值及其上下文，在下一次进程启动后可靠补报上一轮数据，并用明确的采样、持久化、重试和保留边界支持跨端一致统计。

## Requirements

### Requirement: 主进程一轮运行保持稳定身份

客户端 MUST 仅在启用内存指标的主进程累计本轮峰值，复用共享的进程级sessionId/processId，主进程两者相同且为UUID v4。Activity重建、前后台变化以及同进程SDK关闭再初始化 MUST 不封存或重置本轮；恢复同轮时保留原eventId、元数据与峰值。只有识别到新的进程身份才可把旧轮作为历史补报。采集范围 MUST 描述为SDK有效采集区间，不能声称覆盖停用期间或精确进程起止。

#### Scenario: 同进程重建SDK
- **WHEN** 当前进程关闭并重新初始化SDK
- **THEN** 恢复同轮稳定身份和峰值，不发送该轮或生成第二份运行汇总

#### Scenario: 前后台切换和Activity重建
- **WHEN** 应用进入后台、返回前台或Activity重建
- **THEN** 继续同一轮，已记录峰值不回退，其他事件身份关联不变

#### Scenario: 首次运行和子进程
- **WHEN** 首次运行尚无有效采样，或者SDK在子进程初始化
- **THEN** 不生成空历史汇总，子进程不读写主进程峰值状态

### Requirement: 分别累计三项观测最大值

客户端 MUST 分别累计PSS、VSS、Java堆已用字节最大值，三项采集口径保持不变。每项 MUST 保存bytes、首次达到该最大值的occurredAt、foreground及可选Activity场景scene；相等值保留首次上下文，单项失败不清空旧峰值，真实0为有效值。全部指标失败不得生成空事件；一轮至少一项有效才可封存。客户端 MUST 保留采集起点及最后已持久化有效采样时间，且每个峰值时间位于该区间内，不将最后采样称为准确退出时间。

#### Scenario: 三项独立达到最大值
- **WHEN** 同轮三次采样为(100,500,20)、(200,400,80)、(150,450,40)
- **THEN** 保存(200,500,80)，每项保留各自最大值首次发生时的时间、场景和前后台

#### Scenario: 相等、缺失和零
- **WHEN** 某项首次为0，随后缺失，再得到相同最大值但上下文不同
- **THEN** 0可形成有效峰值，失败不清零，相等不覆盖首次上下文

### Requirement: 当前轮快照可靠持久化且不上传

客户端 MUST 在后台持续保存本轮完整快照，出现新高及时持久化，并周期保存最新有效观测截止；不得追加保存全部普通样本。当前快照 MUST 包含稳定eventId、原身份和版本/buildId等元数据及各峰值上下文，成功替换前不得破坏上一份有效快照。写入失败 MUST 保留可恢复版本及待重试状态并记录失败，成功恢复、保存/封存等关键节点 MUST 有可关联日志，不输出密钥。突然终止只保证最后成功持久化的内容，不能保证尚未写入的峰值。

初始化、定时上传、网络恢复、手动flush及正常SDK关闭 MUST NOT 将当前轮加入上传队列或提前作为历史轮次发送。正常关闭可尽力保存，但不得依赖退出回调保证可靠性。

#### Scenario: 本轮有峰值但触发flush
- **WHEN** 当前轮创新高后触发手动flush、网络恢复或定时上传
- **THEN** 本轮只保存在当前快照中，网络只可发送已封存历史轮次

#### Scenario: 原子替换期间失败
- **WHEN** 写盘、同步或替换过程中失败/进程终止
- **THEN** 重启可读取上次或本次完整版本，不把半份JSON当合法快照，旧有效副本不会被提前删除

#### Scenario: 无新高仍持续有效采样
- **WHEN** 后续采样未创新高但仍有效
- **THEN** 峰值不变，周期持久化推进记录的观测截止，不把最后一次新高伪称最后采样

### Requirement: 下次启动先封存上一轮

客户端 MUST 在新轮采样/上传前恢复本地状态，将旧进程完整快照以原eventId和原内容可靠封存为历史任务，封存成功后才建立新轮。封存中断重试 MUST 幂等：已有相同事件时复用，不生成新ID或覆盖重试状态；不能仅凭“曾尝试入队”认定已有可靠副本。封存失败 MUST 保留唯一有效旧快照，不先覆盖为新轮。损坏记录 MUST 有界隔离且明确记录，不能当作有效峰值；当前快照与事件不一致时不得静默覆盖有效记录。

#### Scenario: 新进程补报旧运行
- **WHEN** 当前身份与磁盘快照不同
- **THEN** 先可靠保存旧任务，再建立新轮，旧任务保留原sessionId/processId/版本/buildId和全部峰值

#### Scenario: 封存后创建新轮前再次终止
- **WHEN** 旧事件已持久化但current尚未替换时进程再次终止
- **THEN** 再次启动识别相同ID已有历史任务，最多重发同一事件，不重复计数或丢旧峰值

#### Scenario: 空间或文件操作失败
- **WHEN** 封存无法确保事件持久存在
- **THEN** 不覆盖唯一有效current，不记录虚假封存成功，后续可重试

### Requirement: 历史补报遵守共同协议与确认边界

客户端 MUST 使用v2批量入口和 `memory_peak_summary` / `memoryPeakSummary`，满足配套服务端共同契约，occurredAt等于原lastSampledAt。封存/重试 MUST 不重算峰值或改写原身份/版本/时间。只有HTTP200且requestId、accepted/duplicate/rejected计数及错误定位合法才可逐事件确认；accepted/duplicate才删除对应任务。网络异常、408/429/5xx、响应解析/一致性错误和可重试事件错误 MUST 保留原任务并遵循服务端延迟/有界退避；永久错误或达到尝试上限进入隔离。flush MUST 不绕过退避。

#### Scenario: 新版本启动补报
- **WHEN** 应用升级后上传上一轮事件
- **THEN** 保持旧版本、buildId及原运行身份，不归属新版本

#### Scenario: 写入成功但响应丢失
- **WHEN** 服务端已写入而客户端只观察到超时，随后重试得到duplicate
- **THEN** 原事件不变，duplicate合法确认后才删除，统计仅一轮

#### Scenario: 部分接受和畸形响应
- **WHEN** 批次部分事件可重试，或响应计数/定位不一致
- **THEN** 只确认可可靠判定的已接受/重复事件；畸形响应不导致丢任务，失败项依对应规则保留或隔离

### Requirement: 保留和配额不得使历史事件续期

客户端峰值任务默认 MUST 保留90天，过期以原lastSampledAt计算，年龄恰好90天及更早不再上传；封存/重试/新启动不能延长。活动current不因历史TTL删除，但转为历史前必须检查年龄。队列 MUST 有磁盘配额和尝试上限，默认20MiB和10次；清理优先隔离及最旧历史，不删除正在使用的唯一有效快照。配置与文档 MUST 明确服务端独立窗口和容量边界，不能承诺无限保留。旧memory_sample任务 MUST 隔离/有界淘汰并记录原因，不转换为运行峰值，不影响其他功能队列。

#### Scenario: 超过一周后重新启动
- **WHEN** 上一轮截止距今8天且未超配额/尝试上限
- **THEN** 仍可封存补报，不因旧7天默认误删

#### Scenario: 恰好过期与配额不足
- **WHEN** 旧轮截止距今90天，或空间不足以可靠封存
- **THEN** 过期事件按明确原因处理且不续期；空间失败保留有效current，不误报入队成功

### Requirement: 缩短采样间隔须验证完整路径开销

客户端 MUST 支持前后台独立可配置间隔，初始化和状态变化立即采样，在后台串行执行读取/比较/落盘，不追赶遗漏周期，不在主线程采集或写盘。新默认前后台间隔 MUST 短于原60秒/300秒，并在确定前用同设备同负载对候选与原基线测量完整采样持久化耗时、CPU、主线程影响、写盘次数/字节及短时上涨捕获；不能只测原始读取耗时。设备/构建/负载和测量边界 MUST 可追溯，证据不足时默认值选择任务不得标完成。文档 MUST 明确周期采样仍可能遗漏瞬时尖峰。

#### Scenario: 采样执行晚于调度
- **WHEN** 采样或落盘执行较久、发生前后台切换
- **THEN** 不并发追赶错过周期，按当前状态安排下一次，峰值仍属于同轮

#### Scenario: 频率选择和证据不足
- **WHEN** 候选间隔完成同条件测量，或缺少可用设备
- **THEN** 前者依据完整路径证据确定并同步默认配置/文档；后者保留未完成状态，不声称已验证新默认或端到端完成
